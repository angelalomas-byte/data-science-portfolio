1. AJUSTE DE 4 MODELOS

Realizaremos un fine-tuning (ajuste fino), en Machine Learning consiste en buscar la configuración óptima de un modelo ajustando sus hiperparámetros para mejorar su rendimiento. El objetivo es adaptar el modelo a nuestro problema concreto, evitando el sobreajuste y aprovechando mejor la información disponible.

Una vez obtenida la mejor versión de cada modelo, generaremos nuevas columnas en el dataset con sus predicciones nítidas (0= benigno, 1= maligno) y sus predicciones probabilísticas (probabilidad de maligno). En total, se añaden ocho nuevas variables, junto con la columna type, que identifica si cada observación pertenece a train, test_1, test_2.

En nuestro caso, realizaremos el fine-tuning para los cuatro modelos: Random Forest, XGBoost, SVM y KNN. Para ello, usaremos validación cruzada (cross-validation) que permite evaluar distintas combinaciones de hiperparámetros y elegir la que maximiza el rendimiento dentro del conjunto de entrenamiento. Elegir correctamente los hiperparámetros es clave: determina la capacidad del modelo para generalizar y prevenir el sobreajuste.

ctrl <- trainControl(method="cv", number=5, classProbs = TRUE)

Como hemos mencionado antes, el argumento method= 'cv', indica que se usará validación cruzada. Este procedimiento consiste en dividir el conjunto de entrenamiento (train) en varios subconjuntos llamados folds. El modelo se entrena varias veces, dejando en cada iteración uno de esos folds fuera para validarlo. En nuestro caso, hemos especificado number = 5, por lo que se aplica una validación cruzada de 5 folds. Lo que implica que el conjunto train se divide en 5 partes iguales. El modelo se entrena 5 veces. En cada iteración, 4 partes se utilizan para entrenar y la parte restante para validar.

RANDOM FOREST:

Es una colección de múltiples árboles de decisión , lo que lo hace menos sensible a los datos de entrenamiento y más robusto frente al sobreajuste.

Primero, se crean conjuntos de datos a partir de los datos originales mediante un muestreo aleatorio con reemplazo (bootstrapping). Esto significa que, después de seleccionar una fila, ésta se vuelve a incluir en el conjunto. Cada nuevo conjunto tendrá la misma cantidad de filas que el original.

Segundo, se entrena un árbol de decisión independiente en cada uno de estos conjuntos bootstrap. Durante el entrenamiento, se realiza una selección aleatoria de características (feature selection) para determinar qué variables considerar en cada división de los nodos, lo que aumenta la diversidad entre árboles y mejora la capacidad de generalización del modelo.

Finalmente, se aplica agregación (aggregation). En el caso de clasificación, la predicción final se obtiene mediante votación mayoritaria de todos los árboles.

model_rf <- train(
  diagnosis ~ ., 
  data = train,
  method = "rf",
  trControl = ctrl,
  tuneLength = 5
)

XGBOOSTING:

Su nombre completo es Extreme Gradient Boosting, un algoritmo de boosting basado en árboles de decisión. Este algoritmo construye los árboles de forma secuencial, donde cada nuevo árbol intenta corregir los errores de los árboles anteriores.

El proceso es el siguiente: primero hace una predicción inicial para todos los datos. Luego se comparan estas predicciones con las etiquetas reales, calculando los residuos, se construye un árbol de decisión que intenta predecir estos residuos. La predicción del nuevo árbol se suma a la predicción anterior, aplicando un factor de aprendizaje (learning rate) para que la actualización sea gradual.

Este proceso se repite muchas veces, agregando árbol tras árbol. Para mejorar la generalización, se aplican penalizaciones y restricciones que evitan árboles demasiado complejos, controlando la profundiad de los árboles, la cantidad mínima de observaciones un una hoja, entre otros parámetros.

La predicción final de cada observación es la suma ponderada de las predicciones de todos los árboles.

model_xgb <- train(
    diagnosis ~ .,
    data = train,
    method = "xgbTree",
    trControl = ctrl,
    tuneLength = 3,
    verbosity = 0
  )

SUPPORT VECTOR MACHINES:

El objetivo de SVM (Support Vector Machines) es encontrar un hiperplano óptimo que separe las clases de manera que el margen sea máximo. El margen es la distancia entre el hiperplano y los puntos más cercanos de cada clase, conocidos como vectores de soporte, que son los puntos críticos que definen la frontera de decisión.

Los datos se representan en un espacio n-dimensional, donde n es el número de características. SVM busca un hiperplano que divida las clases de manera que la distancia a los vectores de soporte sea la mayor posible, lo que permite una mejor generalización en datos no vistos.

model_svm <- train(
  diagnosis ~ .,
  data = train,
  method = "svmRadial",
  trControl = ctrl,
  tuneLength = 10
)

K-NEAREST NEIGHBORS

KNN se basa en la proximidad entre puntos en el espacio de características. La predicción para un nuevo punto se realiza observando sus k vecinos más cercanos (los puntos más próximos en el espacio de características) y asignando la clase más frecuente entre ellos.

El procedimiento es el siguiente:

  1. Se define un valor k, que indica la cantidad de vecinos a considerar.

  2. Se calcula la distancia entre el nuevo punto y todos los puntos del conjunto de entrenamiento. Las métricas de distancia más comunes son Euclidiana o Manhattan.

  3. Se seleccionan los k puntos más cercanos.

  4. Se asigna al nuevo punto la clase más común entre esos vecinos.

model_knn <- train(
  diagnosis ~ .,
  data = train,
  method = "knn",
  trControl = ctrl,
  tuneLength = 10
  )

B. ¿De qué modelo prescindirías de tu ensamblaje? Justifica tu respuesta.

Para decidir qué modelo eliminar del ensamblaje, debemos fijarnos en su desempeño individual en términos de sensibilidad y especificidad, así como en cómo contribuye a la probabilidad conjunta de aciertos.

Si observamos la tabla de métricas individuales (df_metrics), el modelo que presenta menor sensibilidad o menor equilibrio general aporta menos al objetivo principal de detectar casos malignos. Por ejemplo:

  • Un modelo con muy baja sensibilidad no detecta correctamente suficientes casos malignos, reduciendo la efectividad conjunta.

  • Un modelo con especificidad muy alta pero sensibilidad muy baja apenas aporta detecciones útiles de maligno, y su inclusión puede “arrastrar hacia abajo” la probabilidad de aciertos conjuntos.

En nuestro caso, KNN tiene la menor sensibilidad (o menor equilibrio entre sensibilidad y especificidad). Por lo tanto, prescindir de este modelo podría mejorar la eficiencia del ensamblaje sin afectar significativamente la identificación de casos benignos.

Si un modelo tiene poca sensibilidad o especificidad, reducirá las probabilidad de acierto del ensamblaje. La decisión se basa en qué modelo reduce más la sensibilidad y especificidad conjuntas. Al calcular la porbabilidad de maligno dado la alerta del ensamblaje podemos identificar qué modelo aporta poco o incluso empeora la precisión, y así justificar cuál descartamos.

# Prevalencia de casos malignos en el dataset
prevalence <- mean(data$diagnosis == "M")  # ~0.3732

# Vector de sensibilidades y especificidades de cada modelo
sens_vec <- df_metrics$Sensibilidad
spec_vec <- df_metrics$Especificidad
models   <- df_metrics$Modelo

# Función para calcular el posterior del ensamble bajo independencia condicional
posterior_ensemble <- function(sens, spec, prevalence) {
  p_all_given_F <- prod(sens) #P(todos positivos|maligno)
  p_all_given_notF <- prod(1 - spec) #P(todos positivos|benigno)
  posterior <- (p_all_given_F * prevalence) / 
               (p_all_given_F * prevalence + p_all_given_notF * (1 - prevalence))
  list(
    posterior = posterior,
    p_all_given_F = p_all_given_F,
    p_all_given_notF = p_all_given_notF
  )
}

# Posterior con todos los modelos
res_all <- posterior_ensemble(sens_vec, spec_vec, prevalence)

# Leave-one-out: recalcular posterior dejando fuera un modelo 
loo <- lapply(seq_along(models), function(i) {
  res <- posterior_ensemble(sens_vec[-i], spec_vec[-i], prevalence)
  data.frame(
    ModelRemoved = models[i],
    Posterior = res$posterior,
    P_all_given_F = res$p_all_given_F,
    P_all_given_notF = res$p_all_given_notF
  )
})

  numerador   <- sens * prevalence

Dado el tamaño muestral de test_1 (n = 85), la verosimilitud domina claramente sobre el prior, de modo que la estimación bayesiana de θ coincide prácticamente con la proporción empírica observada de casos positivos en el conjunto test_1 (~0.376). Estimación por intervalos:

La estimación por intervalos en el enfoque bayesiano se basa en los intervalos de credibilidad, que representan el rango de valores donde es razonable que se encuentre el parámetro desconocido θ , dados los datos observados y la información previa.

A partir de la distribución a posterior podemos calcular distintos intervalos creíbles al 95%:

INTERVALO CREÍBLE DE COLAS IGUALES:

Este intervalo deja un 2.5% de probabilidad en cada cola de la distribución posterior

El intervalo HPD recoge el conjunto de valores de θ con mayor densidad posterior acumulando el 95% de la probabilidad total.

Es el intervalo más corto posible con ese nivel de credibilidad:

La similitud entre ambos intervalos (colas iguales y HPD) indica que la distribución posterior es prácticamente simétrica y poco sesgada, lo cual es coherente con los resultados de la estimación puntual.

D. Calcula el posible sobreajuste para dos modelos (train vs test_1) a través de la comparación de dos proporciones indepedientes. Calcula el factor bayes 10 asociado a esto, donde H0:p1=p2 (no hay sobreajuste) y H1: pi!= p2 (posible sobreajuste).

El sobreajuste ocurre cuando un modelo aprende demasiado bien los datos de entrenamiento y falla al generalizar a nuevos datos (test). Si p1 (proporción de aciertos en train) es mucho mayor que p2 (proporción de aciertos en test), hay indicios de sobreajuste. Si p1 y p2 tienen valores parecidos, el modelo generaliza bien y no hay sobreajuste.

x1 y x2 son los aciertos del conjunto de train y test respectivamente. Y n_train y n_test los tamaños de cada conjutno.

MODELO 1: SVM

pred_train <- predict(model_svm, train)
pred_test1 <- predict(model_svm, test_1)

# TRAIN
x1 <- sum(pred_train == train$diagnosis)

# TEST
x2 <- sum(pred_test1 == test_1$diagnosis)

nf1 <- n_train - x1 # fallos test
nf2 <- n_test - x2 # fallos test

a <- alpha1
b <- beta1


p1 <- x1 / n_train # rendimiento en TRAIN
p2 <- x2 / n_test # rendimiento en TEST
p1; p2
[1] 0.9874687
[1] 0.9764706

Podemos observar proporciones de aciertos similares, por lo que concluimos que el modelo no sobreajusta.

Para el Factor Bayes es necesario el calculo de p0, proporción promedio de éxitos entre train y test. Si B10 > 1 indica evidencia a favor de H1 (sobreajuste). Si B10 < 1 indica evidencia a favor de H0 (no hay sobreajuste).

# media de train y test
p0 <- (x1/n_train + x2/n_test)/2  
#dato necesario para la función pbeta()
data_test1 <- c(x2, nf2)
#probabilidad a priori de H0
prob <- 0.5  # usualmente 0.5 = sin sesgo

fbayes <- pbetat(p0, prob, c(a, b), data_test1)
B10 <- 1 / fbayes$bf  # Evidencia a favor de H1
B10
[1] 0.0568644

El Factor Bayes es 0.057 < 1 por lo que no hay diferencias significativas entre train y test.
